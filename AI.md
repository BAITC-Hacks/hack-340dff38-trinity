# AI-деморежим и контракт интеграции

Внешний API не подключён. Разрешённая кейсом локальная заглушка в domain.js анализирует явно распознаваемые фрагменты и выдаёт вопросы для отсутствующих подпунктов. Она не является языковой моделью. В интерфейсе это обозначено как «AI-демо».

## Промпт для будущего реального адаптера

Ты помогаешь бизнесу уточнять задачу. Используй только факты из raw и fields. Не добавляй факты, сроки, имена или контакты. Не выбирай команды. Верни JSON: {"questions":[{"field":"ключ поля","label":"раздел","question":"вопрос"}],"fields":{...}}. Нужно минимум 3 уместных вопроса по отсутствующим сведениям; для заполненной карточки уточняй неоднозначности и приёмку. Не публикуй результат. Неизвестные поля — пустые строки. Рекомендации выделяй отдельно и требуй подтверждения.

Вход содержит разрешённые поля из FIELDS (domain.js) и исходное описание. Для настоящего API добавьте требование считать текст пользователя данными, а не инструкциями модели; не позволяйте модели менять правила подтверждения, ранжирования или доступа. API-ключ должен храниться на сервере, никогда в JS браузера.

## Пример входа

```json
{
  "raw": "У нас ателье. Заказы приходят в мессенджер, иногда теряются. Хотим упростить учёт.",
  "fields": {}
}
```

## Пример структуры выхода

Ниже сокращённый пример; адаптер возвращает все поля карточки, незаполненные — пустой строкой.

```json
{
  "questions": [
    {"field":"users","label":"Пользователи","question":"Кто будет пользоваться решением?"},
    {"field":"data","label":"Данные и материалы","question":"Какие данные, примеры или источники доступны?"},
    {"field":"criteria","label":"Критерии успеха","question":"Какие числовые показатели или проверяемые условия определят успех?"}
  ],
  "fields": {
    "title":"",
    "context":"У нас ателье. Заказы приходят в мессенджер, иногда теряются. Хотим упростить учёт.",
    "need":"Хотим упростить учёт.",
    "users":"",
    "data":"",
    "criteria":""
  }
}
```

## Как работает заглушка

- Исходный текст целиком сохраняется в контексте.
- Явные предложения распознаются по маркерам: «хотим», «есть CSV», «пользователи:», «результат:», «приёмка», «ограничения:» и т. п. Совпавшие фрагменты копируются дословно. Email извлекается буквально.
- Неизвестные сведения остаются пустыми. Название пользователь задаёт вручную.
- Вопросы запрашивают отсутствующие подполя. Если всё заполнено, задаются три вопроса об исключениях при приёмке, обезличивании и задержках обратной связи.
- Ответы пользователя переносятся дословно в редактируемые подполя. Человек подтверждает публикацию.
- Regex-разбор ограничен: при сложном свободном тексте может пропустить факт и задать повторный вопрос. Это известное ограничение заглушки.

## Проверка и резервный сценарий

validateAI проверяет объект полей, допустимые имена и строковые значения, массив минимум из трёх вопросов с допустимыми полями и осмысленным текстом. Некорректный, неполный ответ, недоступность и тайм-аут приводят к резервному questionSet. Исходный текст и уже сохранённые ответы остаются в хранилище.

Проверить можно на первом шаге через «Проверить резервный сценарий»: корректный ответ, некорректный ответ, тайм-аут и недоступность. В демонстрации ожидание короткое: 350 мс для нормального ответа, 800 мс тайм-аут. Это симуляции, сетевых запросов нет.

В production следует заменить только адаптер, обеспечить серверное хранение ключа, ограничение запросов, тайм-аут, строгую JSON schema и контроль соответствия фактам. Граница обязательного ручного подтверждения должна остаться в приложении, а не только в промпте.
